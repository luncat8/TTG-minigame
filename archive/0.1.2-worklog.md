# 0.1.2 worklog

## Steps

1. Added the `rotateGravityEachTurn` rule to `RULE_DEFINITIONS` in `src/model.js` (default off, label `Rotate gravity every turn`), so defaults, the checkbox list, `setRule`, and `clean` pick it up with no other wiring.
2. Extracted `advanceGravity` in `src/model.js` and used it from both `rotateGravity` and `finishTurn`. With the rule on, the turn boundary advances gravity one step clockwise after the turn passes; the direction change alone restacks the board on the next placement, matching manual rotation. A game-over turn does not rotate, and `clean` still resets to down.
3. Kept manual rotation composable: `rotatedThisTurn` still allows one manual step per turn, which stacks with the automatic one.
4. Updated the bot lookahead in `src/bots.js`: `bestReplyGain` now evaluates the next player at the gravity they inherit (base + 1 under the rule) plus their own manual option, and `evaluateCandidate` restacks the trial toward the inherited gravity before measuring standing balance, since the next placement restacks every line.
5. Updated the status line in `src/app.js` to name the automatic rotation while the rule is on. The rotate button and keyboard `R` remain available for an extra manual step.
6. Added the rule line to `draft.txt`.
7. Added model tests (rule off holds gravity, four-turn cycle, stacking with manual rotation, mid-game enabling, game-over without rotation) and bot tests (legality self-play for 2-6 players, termination for 4-6 players, denial pricing that the reply gravity follows the inherited rotation).

## Validation

- `npm test`: 57 tests pass.
- `node --check` passes for all four source scripts and `git diff --check` is clean.
- Old-versus-new bot comparison over 60 random settled positions with default rules: identical chosen cell and rotation flag, so the rule-off behavior is unchanged.
- Self-play measurement (20 games each, 7×7, heuristic bot, `experiments/logs/0.1.2-selfplay-rotate.txt`): rule off finishes at 49 turns with 0 points; rule on never finishes at 2-3 players within the 400-turn cap (points keep accruing), while 4 players finish at 258 turns.
- Headless Chromium on `file://`: the rules list renders the new unchecked checkbox; enabling it updates the status text; two human placements advance gravity down → left → up; keyboard `R` adds one more step (right) inside the turn; no console errors and no horizontal overflow.

## Findings

- The rotation keeps removals in pace with placements, so symmetric bot games with 2-3 players cycle forever under the rule. The board never fills and both scores grow together. This is rule balance rather than a model defect: every move is still legal and every turn resolves normally. 4-6 players terminate.
- Deterministic self-play is opening-sensitive even without the rule: with no random opening the default rules score 0 points and fill the board in one turn per cell, while a single random opening produces ~600-turn scoring games. Experiments must fix the opening procedure before comparing rules.

If the endless dynamic is unwanted, try the rule with `Remove any group of four or more` off, or add a turn limit, and re-measure with `experiments/selfplay.js` style runs.
