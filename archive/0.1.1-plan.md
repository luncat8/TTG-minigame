# 0.1.1 — Prototype-informed interface pass

## Objective

Carry the useful visual language from the early prototypes into the tested game without bringing back their duplicate game logic or conflicting turn rules.

## Prototype decisions

### Keep from `prototype/GPT5L.html`

- Use its soft lavender page background (`#f7f4f8`).
- Use its readable text symbols and player order: `X`, `O`, `△`, `□`.
- Use its pastel pink, blue, green, and purple occupied-cell backgrounds.
- Keep the upright board and emphasize the edge toward which gravity falls.

The production game supports six players, so extend the symbol set with `☆` and `+` and add similarly muted yellow and peach backgrounds.

### Keep from `prototype/s5/`

- A short game explanation rather than exposing an unexplained board.
- Separate cards for setup, rules, and players.
- Player rows that combine identity, score, controller, and bot strategy.
- A plainly visible current-gravity readout and a rotate action that names the next direction.
- Preview the cell where a mark will land, not merely the source cell under the pointer.

### Do not carry forward

- Prototype-local rules engines, bots, event logs, and full-DOM board rebuilding. The pure typed-array model, tested bot, and canvas renderer remain authoritative.
- Automatic gravity rotation from `s5`; the current once-per-turn optional rotation is part of the established game rules.
- The prototypes' smaller player and board ranges.

## Interface design

- Use a responsive board-and-sidebar layout on wide screens and one column on narrow screens.
- Render separated rounded cells on canvas, with text glyphs centered on pastel occupied tiles.
- Keep the gravity edge and arrow within the canvas so all four directions have one consistent treatment.
- Replace the dense player table with accessible player cards. Keep inactive slots visible because their marks and scores remain part of the game state.
- Keep keyboard operation: arrows move the source cursor, Enter or Space places, and R rotates.

## Landing preview

Add a pure model query that returns the destination of a legal placement after stable settling. It must account for the current gravity, occupied cells between the source and gravity edge, and an unsettled board immediately after rotation. Use the query for pointer and keyboard ghost previews without mutating game state.

## Acceptance criteria

- The first four symbols, player tile colors, and page background match `GPT5L.html`.
- The page has no horizontal overflow at desktop or 390 px mobile width.
- Player strategy labels are not clipped at desktop width.
- Pointer and keyboard previews appear at the post-settle destination in all four gravity directions.
- Existing game behavior, bot scheduling, live options, file operation, and accessibility remain intact.
- All Node tests and a headless-browser interaction smoke test pass without console errors.
